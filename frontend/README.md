# Carte Pro web app

Built with React, TypeScript, and Vite.

## Setup

Install dependencies:

```bash
npm install
```

Create the environment file:

```bash
cp .env.example .env
```

Start the dev server:

```bash
npm run dev
```

The app runs on `https://localhost:5173`, over local HTTPS using the
certificates generated by `../generate-certs.sh` (see the root README).

## Environment variables

| Variable | Purpose |
| --- | --- |
| `BACKEND_URL` | The backend's own origin. Vite proxies every `/api/v1/*` request there, so the app never talks to the API directly. |
| `VITE_PORT` | Optional, overrides the dev server port (defaults to 5173). |

If `BACKEND_URL` is missing or points at the wrong scheme (`http` instead of
`https`, for example), every API call fails with a 502 from the Vite proxy
rather than a normal error from the backend.


## Structure

```text
src/
  api/          axios calls to the backend, grouped by resource
  components/   pieces shared across pages (header, footer, modal, QR code...)
  pages/        one file per screen (home, login, register, employee space...)
  types/        shared TypeScript types for API data
```

`App.tsx` holds which screen is currently shown, there is no router. Each
page receives callbacks as props to ask the app to switch screens.

## Notes

- Not everything calls the API yet. `Admin.tsx`'s national dashboard
  (KPIs, region ranking, referral requests) and the homepage's partner
  preview (`src/pages/partners.tsx`) still use hardcoded data. Everything
  else does real requests through `src/api/`.
- Two separate QR libraries: `components/Qr.tsx` generates the employee's
  code (`qrcode.react`), `components/QrScanner.tsx` reads one through the
  camera (`@zxing/browser`, needs Node 24, works fine on 20 with a warning).
- This is a demonstrator, not a live payment service. Any screen showing a
  real-looking amount should wrap it in `<Amount>` and add a
  `<SimulationNotice />` (both in `components/Simulation.tsx`), see
  `Employee.tsx` for an example.
- Every page's CSS is bundled together regardless of which screen is
  active, since `App.tsx` imports all pages eagerly. Class names are
  effectively global: if two rules can collide, use a compound selector
  (`.badge.badge-warning`) so it wins on specificity, not load order.
